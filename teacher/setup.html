ONE-TIME TEACHER SETUP

Connect your results sheet.

These files are prepared for your spreadsheet. Google requires you to authorise the script in your own account. No student results will be sent until the deployment is connected.

  1. Open your spreadsheet and its script editor.
    Open your results spreadsheet ↗, then choose Extensions → Apps Script. Keep the sheet’s General access set to Restricted.
  2. Add the three files below.
    Replace the default Code.gs content with the first file. Use + → Script to add QuestionBank, then + → HTML to add Dashboard. Paste the matching content into each and save.
    Download Code.gsDownload QuestionBank.gsDownload Dashboard.html

  3. Run the setup.
    In the editor’s function menu choose setupLearningLab, click Run and grant access to your spreadsheet. Use the function name without a trailing underscore. If Google requests permission to identify your signed-in account, authorise it using the account that owns the deployment. It creates Answers and Sessions tabs and shows a randomly generated teacher password in the execution log. Save that password privately. Existing tabs are left intact.
  4. Deploy the web app.
    Choose Deploy → New deployment → Web app. Set Execute as: Me and Who has access: Anyone, then deploy. This allows students to submit answers without access to your sheet. The teacher dashboard still requires the server-checked teacher password.
  5. Send me the Web app URL ending in /exec.
    It starts with https://script.google.com/macros/s/. This URL is safe to share here. Do not send your teacher password. I’ll connect the URL to the platform and verify a test record with you.

What will be recorded?

All four separate question simulators use the same recorder. The Answers tab stores a name, optional class, course, topic, quiz mode, question, selected answer, correct answer and timestamps. The Sessions tab stores completed quiz scores and identifies retry sessions. Partial quizzes remain visible in the answer history.

Google’s server calculates correctness against the question bank. A student’s name is self-reported. These records support practice and feedback; they are not verified exam identities.

If the setup function is missing or “Sign in to view results” appears

If the function menu only lists doGet, doPost, loginTeacher, logoutTeacher and getTeacherResults, copy the updated Code.gs above, replace the contents of your existing Google script file (it may be named Código.gs), save and refresh the editor. Choose setupLearningLab from the menu. The new setup and reset entries verify your Google account before making changes.

Running getTeacherResults in the editor produces “Sign in to view results” because it expects a dashboard login token. Use the teacher results page to view records.

Resetting the password or updating the script

To reset the password, run resetTeacherPassword from the Apps Script editor. It generates a new password and expires existing teacher logins. Do not share the new password in chat.

After changing the script files or question bank, use Deploy → Manage deployments → Edit → New version → Deploy. Keep the same deployment URL. When we add new question banks, we’ll update QuestionBank.gs too.

Connection failures and shared classroom devices

Students see “saved” only after Google confirms the write. Unconfirmed answers are retried and retained in the current tab across reloads, where browser storage is available. Keep the tab open until all answers are saved; closing it can lose pending answers. Name details are remembered only in the current browser tab. Students should check the displayed name before each quiz.

If your school account does not offer Anyone, its administrator may restrict public web apps. Tell me which access options you see so we can adapt the setup.
