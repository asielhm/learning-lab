# Google Sheets results

Install using the platform's [`teacher/setup.html`](../teacher/setup.html). This deployment is not connected until the spreadsheet owner creates it and its `/exec` URL is set in `assets/records/config.json`.

The sheet ID is prefilled from the user-provided spreadsheet. Run the visible `setupLearningLab` function in the editor to add Answers and Sessions without changing existing tabs. `resetTeacherPassword` issues a new password. Both wrappers call `requireOwner_`, which requires a nonempty active Google email matching the effective execution user. In the owner-executed web app, anonymous users and other signed-in accounts cannot initialise the sheet or reset the password. Keep the existing Execute as Me deployment setting. Authorising the script in the editor may request the additional user email scope. Internal helpers still end in `_` and cannot be called through `google.script.run`. Do not remove the owner check from the visible wrappers. The other public entry points are `doGet`, `doPost`, `loginTeacher`, `logoutTeacher` and `getTeacherResults`. `doGet` returns a login shell with no records; `doPost` is write-only and returns an acknowledgement, never student data. Each read requires a server-issued, one-hour teacher token stored in Google's script cache. Logout removes that token, and resetting the teacher password invalidates all tokens. Password salts/hashes live in Script Properties; neither passwords nor tokens belong in GitHub or chat. Tokens remain in dashboard memory and clear on reload. The randomly generated 40-character password avoids relying on a weak classroom password. Failed sign-ins have a shared, server-side rate limit.

The Google web app must execute as the owner and allow Anyone to reach its login/submission endpoints. The underlying sheet stays Restricted. No service-account credentials, public sheet exports, or client-side password gates are used. The deployment URL is public routing configuration, not a secret. Anyone with it can send submissions; student identities are self-reported. This is suitable for formative practice rather than tamper-proof assessments. Correctness is calculated server-side from the canonical question bank, not a posted score.

Every submitted answer has a stable session/ordinal ID. Writes use ScriptLock; repeated deliveries do not duplicate answers or summaries. A retry repairs a missing session summary after a partial write. Invalid courses, question IDs, answer options, identities and counts are rejected. Text that could be interpreted as a spreadsheet formula receives a zero-width prefix. The original tab headers must match; mismatched tabs cause a setup error rather than overwriting data. Keep the Answers and Sessions tabs as generated.

The browser posts a hidden form to Google and waits for a Google-origin `postMessage` receipt with a random nonce and matching event ID. Only acknowledged answers are removed from the pending queue. Failed deliveries retry after 20 seconds, on reconnect, or manually. Pending records use sessionStorage, not persistent shared-device storage; closing the tab can discard them. Apps Script quotas/availability can delay saves. The dashboard's 50-row pages are filtered server-side; all data stays on Google. Its accuracy metric is total correct answers divided by total answered questions across the selection.

Update `QuestionBank.gs` with `python3 tools/build_google_question_bank.py` after changing any source question bank, then deploy a new Apps Script version. The static website cannot update the owner's Google deployment itself. Current scope is the four separate revision simulators; inline lesson/model checks and the external Heart Lab site are not recorded.

Run `node tests/google-records-server.cjs` for backend validation, authentication, scoring, deduplication and partial-write tests against a simulated Apps Script runtime. Run `node tests/google-records-browser.cjs` with a local static server for the browser's identity flow, receipts, retries, queued reloads and mobile UI. These tests cannot replace a final live Google deployment check.
